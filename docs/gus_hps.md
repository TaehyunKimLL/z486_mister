# Gravis Ultrasound: FPGA 프런트엔드 + HPS(ARM) 합성 설계

상태: **설계 검토 / 미구현**
대상: z486 코어에 GUS(Classic, GF1)를 추가한다. 추가 하드웨어나 핀은 쓰지 않는다.

관련 문서: [외장 ISA (LPC 브리지)](isa_over_lpc_userport.md). I/O 대기 경로와 DMA/IRQ 연결 방식을 공유한다.

---

## 1. 목표와 범위

- DOS 게임과 데모에서 GUS를 인식하고 재생하게 한다(`ULTRASND` 환경변수, ULTRINIT, 게임 자체 드라이버).
- **레지스터, 타이머, DMA, IRQ, 샘플 RAM 접근은 FPGA**가 처리하고,
  **32보이스 웨이브테이블 합성만 HPS(Cortex-A9)**가 처리한다.
- 합성 결과는 MiSTer에 이미 있는 **ALSA 경로**(`sys/alsa.sv`)로 코어 믹서에 들어가
  HDMI/아날로그로 나간다.

| 포함 | 제외 |
|---|---|
| GF1 보이스 32개, 볼륨 램프, 루프, 팬 | 녹음(샘플링, 레지스터 48h/49h) |
| 샘플 RAM 1 MB (DRAM I/O, DMA 업로드) | GUS MAX / CS4231 코덱, GUS PnP(AMD InterWave) |
| AdLib 호환 타이머 1/2 (2x8h/2x9h) | GUS MIDI UART의 실제 입출력(상태만 응답) |
| 웨이브테이블 / 볼륨 램프 / DMA TC / 타이머 IRQ | SBOS / MEGA-EM 같은 SB 에뮬레이션 TSR의 NMI 경로 |

## 2. 왜 분할하는가

| 방식 | 문제 |
|---|---|
| GUS 전체를 ARM에서 처리 | HPS↔FPGA 제어 경로(`hps_io`)는 MiSTer Main이 폴링한다. I/O **읽기** 한 번에 수십~수백 µs가 걸리고 Linux 스케줄링에 따라 ms 단위로 튄다. 실제 GUS는 1–2 µs 안에 응답한다 |
| GUS 전체를 FPGA에서 처리 | GF1 32보이스 보간·볼륨·믹싱 파이프라인과 1 MB 샘플 RAM 대역이 필요하다. z486은 이미 CPU/x87/SVGA로 FPGA 자원을 많이 쓰고 있다 |
| **분할 (이 설계)** | 읽기는 FPGA 섀도로 즉시 응답하고, 쓰기는 대기 없이 로그로 넘긴다. ARM은 약 1 ms 블록 단위로 합성한다. 정확도는 DOSBox GUS와 비슷한 수준이다 |

ARM 연산량(추정): 32보이스 × 19.3 kHz × 보이스당 약 20 연산 ≈ 초당 1,200만 연산.
Cortex-A9 800 MHz 코어 하나의 몇 % 수준이다(DOSBox GUS는 더 느린 ARM에서도 돈다).

│                                ├ 레지스터 섀도     │  DDR3    │ ├ 쓰기 로그 소비          │

│                                ├ DMA 엔진 ◄─ dma.v │ ◄──────► │ ├ GF1 합성 (1 ms 블록)    │
│                                ├ IRQ 상태 ─► pic   │          │ ├ 보이스 상태/IRQ 이벤트  │

## 4. HPS와 FPGA의 DDR3 공유

### 4.1 근거

DE10-nano의 DDR3는 HPS SDRAM 컨트롤러에 붙어 있고, FPGA는 f2sdram 브리지(`sys/sysmem.sv`)로 같은
물리 메모리에 접근한다. z486은 이미 이 경로를 쓴다.

| 용도 | 물리 주소 | 방향 | 코드 |
|---|---|---|---|
| 부트 이미지 | `0x300C0000 +` | HPS 쓰기 → FPGA 읽기 | `src/system.sv:1028,1040` |
| SVGA 프레임버퍼 | `0x3E000000 +` 부근 | FPGA 쓰기 → 스케일러 읽기 | `z486_mister.sv:1132` |
| ALSA 오디오 | Linux 할당 | HPS 쓰기 → FPGA 읽기 | `sys/alsa.sv` |

`DDRAM_ADDR[28:0]`은 64-bit 워드 주소다. 코어의 `{4'h3, ...}` 주소는 물리 `0x3xxxxxxx`에 해당한다.

### 4.2 GUS 공유 영역 (제안)

기준 주소 `GUS_BASE = 0x3D000000`, 크기 2 MB. MiSTer Main/Linux 메모리 맵에서 비어 있는지
구현 전에 확인한다(부트 영역, 프레임버퍼, 스케일러 버퍼와 겹치지 않아야 한다).

| 오프셋 | 크기 | 쓰는 쪽 | 내용 |
|---|---|---|---|
| `0x000000` | 1 MB | FPGA | 샘플 RAM (GUS DRAM 주소 그대로) |
| `0x100000` | 64 B | FPGA | 헤더: 매직 `"Z486GUS1"`, 버전, 활성화 플래그, 현재 시각(µs), 로그 쓰기 포인터 |
| `0x100040` | 64 B | HPS | 헤더: 데몬 매직, 하트비트, 로그 읽기 포인터, 처리 완료 로그 인덱스 |
| `0x101000` | 64 KB | FPGA | 쓰기 로그 링버퍼 (8,192 × 64-bit) |
| `0x111000` | 4 KB | HPS | 보이스 상태 블록 (32보이스 × 16 B) + 기준 로그 인덱스 |
| `0x112000` | 4 KB | HPS | IRQ 이벤트 링 (512 × 64-bit) + 쓰기 포인터 |

### 4.3 일관성 규칙

- **캐시**: f2sdram은 ARM 캐시와 일관성이 없다. `gusd`는 `/dev/mem`을 `O_SYNC`로 열어
  영역 전체를 **캐시 없이** 매핑한다.
- **샘플 RAM 사본**: 합성할 때 캐시 없는 메모리를 계속 읽으면 느리다. `gusd`는 캐시되는 1 MB 사본을 두고,
  로그의 "DRAM 쓰기 범위" 항목(6.2절)에 해당하는 구간만 공유 영역에서 복사한다.
- **FPGA → HPS 순서**: FPGA는 로그 항목을 먼저 쓰고 **쓰기 포인터를 마지막에** 쓴다. 같은 f2sdram 포트 안에서
  쓰기 순서는 유지된다. `gusd`는 포인터를 읽은 뒤 `dmb`를 넣고 항목을 읽는다.
- **HPS → FPGA 순서**: `gusd`는 상태 블록과 이벤트를 쓰고 `dsb`를 넣은 뒤 포인터를 갱신한다.
  FPGA는 포인터를 먼저 읽고 데이터를 읽는다.

## 5. FPGA: `gus_front`

### 5.1 포트 (기본 base = 240h)

| 포트 | 이름 | 처리 |
|---|---|---|
| 2x0h | Mix control | 래치. bit6으로 2xBh의 IRQ/DMA 선택 |
| 2x6h | IRQ status | FPGA 상태에서 즉시 응답 |
| 2x8h / 2x9h | AdLib 타이머 제어 / 데이터 | FPGA 타이머 |
| 2xBh | IRQ / DMA control | 래치 (IRQ/DMA 번호 설정) |
| 2xFh | Register control (rev 3.7+) | 래치 |
| 3x0h / 3x1h | MIDI control / data | 상태만 응답(TX empty) |
| 3x2h | Voice select | 래치 |
| 3x3h | Register select | 래치 |
| 3x4h / 3x5h | Data low / high | 레지스터 파일 접근 (5.2절) |
| 3x7h | DRAM I/O | DDR 샘플 RAM 읽기/쓰기 (대기 있음) |

z486 내부 장치는 240h–24Fh, 340h–347h를 쓰지 않는다([충돌 표](isa_over_lpc_userport.md#56-내부-장치와의-충돌)).

### 5.2 레지스터 파일

- **보이스 레지스터 (00h–0Dh 쓰기, 80h–8Dh 읽기)**: 보이스 제어, 주파수, 시작/끝/현재 주소, 램프 속도/시작/끝,
  현재 볼륨, 팬, 볼륨 제어. 32보이스 × 14개 × 16-bit를 M10K에 둔다.
- **글로벌 레지스터**: 0Eh 활성 보이스 수, 0Fh/8Fh IRQ 소스, 41h DMA 제어, 42h DMA 시작 주소,
  43h/44h DRAM 주소, 45h 타이머 제어, 46h/47h 타이머 카운트, 4Ch 리셋.
- **쓰기**: 섀도를 즉시 갱신하고, 합성에 영향을 주는 레지스터는 쓰기 로그에 남긴다. CPU는 기다리지 않는다
  (로그가 가득 찼을 때만 대기, 6.3절).
- **읽기**: 섀도에서 즉시 응답한다. 재생 중 바뀌는 값(현재 주소 8Ah/8Bh, 현재 볼륨 89h,
  보이스/볼륨 제어의 정지 비트)은 HPS가 보내는 상태 블록으로 갱신한다(5.5절).

### 5.3 타이머와 IRQ

- 타이머 1(80 µs 단위), 타이머 2(320 µs 단위)는 FPGA 카운터로 구현한다. 정밀해야 하므로 HPS에 넘기지 않는다.
- IRQ 소스: 타이머 1/2, DMA TC, 웨이브테이블 끝, 볼륨 램프 끝, (MIDI는 발생하지 않음).
  2x6h와 8Fh 읽기 규칙(8Fh를 읽으면 해당 보이스 IRQ가 지워짐)은 GF1 동작을 따른다.
- 웨이브테이블/램프 IRQ는 HPS 이벤트 링(4.2절)에서 온다. FPGA는 이벤트를 받으면 보이스별 pending 비트를 켜고
  PIC 출력에 반영한다.
- PIC 연결: `interrupt[n] |= gus_irq & (gus_irq_sel == n)` 형태([IRQ 연결](isa_over_lpc_userport.md#53-irq-srcsystemsv)과 같은 방식).

### 5.4 DMA

- 41h의 enable 비트가 켜지면 `gus_front`가 선택된 채널의 DRQ를 `dma.v`에 올린다.
  `dma.v`의 기존 채널 인터페이스(`dma_N_req/ack/readdata`)를 쓰고, 8237이 전송을 주도한다.
- 받은 바이트/워드는 샘플 RAM(DDR)에 쓴다. 41h의 옵션을 따른다: 8-bit 데이터 MSB 반전(unsigned → signed),
  16-bit 채널 주소 변환, 속도 분주.
- DDR 쓰기가 밀리면 `dma_N_ack` 전에 DRQ를 잠시 내려서 흐름을 조절한다.
- TC에서 DMA TC IRQ를 발생시킨다(41h bit5).
- 전송이 끝나면 쓰기 범위를 "DRAM 쓰기 범위" 로그 항목 하나로 남긴다.

### 5.5 HPS 상태 반영과 경쟁 처리

CPU가 보이스 레지스터를 쓴 직후 HPS가 **그 쓰기 이전 기준으로 계산한** 현재 주소를 보내면,
새로 쓴 값을 옛 값이 덮어쓰게 된다. 이를 막는다.

- 상태 블록에는 "로그 인덱스 N까지 반영한 결과"라는 기준 인덱스가 들어 있다.
- FPGA는 보이스마다 마지막 CPU 쓰기의 로그 인덱스를 기억한다.
- **보이스의 마지막 쓰기 인덱스 > N이면 그 보이스에 대한 HPS 값을 무시**한다. 다음 블록에서 다시 받는다.

현재 주소 읽기를 더 정확히 하려면(선택), FPGA가 마지막 상태 이후 경과 시간 × 주파수로 주소를 선형 외삽한다.
루프 경계는 무시하고 끝 주소에서 멈춘다.

### 5.6 DDR 포트 중재 (`ddr_arb`)

지금 `DDRAM` 포트는 `boot_done`으로 부트 로더와 프레임버퍼가 번갈아 쓴다(`src/system.sv:1036-1045`).
이를 3-way 중재기로 바꾼다.

| 요청자 | 우선순위 | 트래픽 |
|---|---|---|
| 부트 로더 | 부트 중 단독 | – |
| SVGA 프레임버퍼 | 높음 (버스트) | 큼 |
| GUS (3x7h, DMA, 로그, 상태 폴링) | 버스트 사이 | 초당 1 MB 이하 |

- 3x7h 읽기는 CPU가 기다리므로 GUS 요청의 최대 대기 시간을 제한한다(프레임버퍼 버스트 1회 이하).
- GUS 로그는 FPGA 안에 작은 FIFO(64 항목)를 두고 DDR에 모아서 쓴다.

### 5.7 z486 연결 변경점

| 파일 | 변경 |
|---|---|
| `src/iobus_adapter.sv` | 외부 대기 입력(`io_ext_sel/io_ext_ready`) 추가. LPC 설계와 공통 |
| `src/system.sv` | `gus_cs` 디코드, `iobus_readdata8` mux 추가, `ddr_arb`, PIC/DMA 연결 |
| `src/soc/gus/gus_front.sv` (신규) | 5.1–5.5절 |
| `src/soc/gus/gus_ddr.sv` (신규) | 샘플 RAM 접근, 로그 기록, 상태/이벤트 폴링 |
| `z486_mister.sv` | OSD 항목, `alsa_l/r`을 믹서 볼륨에 연결 |

OSD 항목(제안):
- `GUS: Off / On`, `GUS base: 240h / 220h / 260h` (220h는 내장 SB와 겹치므로 SB를 끌 때만)
- `GUS IRQ: 11 / 7 / 5 / 3`, `GUS DMA: 3 / 1 / 5 / 6 / 7`

기본값은 z486 내부 장치와 겹치지 않는 **`ULTRASND=240,3,3,11,11`**(DMA 3, IRQ 11)이다.
IRQ 5/7이나 DMA 1/5를 고르면 내장 SB와 겹치므로 OSD에서 막는다.

## 6. 쓰기 로그와 상태 형식

### 6.1 로그 항목 (64-bit)

| 비트 | 필드 | 내용 |
|---|---|---|
| 63:33 | `ts` | 시각(µs, 31-bit, 순환). FPGA 자유 카운터 |
| 32:29 | `type` | 0: 보이스 레지스터, 1: 글로벌 레지스터, 2: DRAM 쓰기 범위, 3: 리셋, 4: 활성 보이스 수 |
| 28:24 | `voice` | 보이스 번호 |
| 23:16 | `reg` | 레지스터 번호 (DRAM 범위일 때는 길이 상위 비트) |
| 15:0 | `data` | 값 (DRAM 범위일 때는 시작 주소 / 길이 하위) |

DRAM 범위 항목은 두 개로 나눠 [시작, 길이]를 보낸다. FPGA는 연속된 3x7h 쓰기를 한 범위로 합친다.

### 6.2 보이스 상태 블록 (보이스당 16 B)

`current_addr`(32), `current_vol`(16), `voice_ctrl`(8), `vol_ctrl`(8), 예약. 블록 앞부분에 기준 로그 인덱스(5.5절).

### 6.3 흐름 제어

- 로그 링이 가득 차면 FPGA는 다음 GUS I/O 쓰기에서 `io_ext_ready`를 늦춰 CPU를 잠시 세운다.
  이 경우에도 로그 항목은 **버리지 않는다**.
- `gusd` 하트비트가 약 100 ms 이상 멈추면(데몬 없음), FPGA는 로그를 버리고 레지스터 섀도만 유지한다.
  CPU가 멈추는 일은 없고, 소리만 나지 않는다.

## 7. HPS: `gusd`

### 7.1 동작

1. 시작: `/dev/mem`에서 `GUS_BASE`를 매핑하고 FPGA 헤더의 매직을 확인한다. 없으면 100 ms 간격으로 재시도한다
   (z486이 아니거나 GUS가 꺼진 상태).
2. 약 1 ms 주기로 반복한다(`SCHED_FIFO`, `clock_nanosleep`).
   - FPGA 현재 시각 T를 읽는다.
   - `ts < T`인 로그를 순서대로 반영하면서 [이전 T, T) 구간을 합성한다.
     로그 항목은 자기 `ts` 위치의 샘플에 적용한다(블록 안에서 샘플 단위로 정확).
   - 웨이브테이블/램프 IRQ 조건을 만나면 이벤트 링에 기록한다.
   - 보이스 상태 블록과 기준 로그 인덱스를 쓰고 하트비트를 올린다.
   - 결과 PCM을 ALSA 출력 레이트로 리샘플해 `snd_pcm_writei`로 보낸다.
3. 합성 코어: DOSBox-X의 GUS 코드(GPLv2, PicoGUS의 `gus-x.cpp`가 여기서 파생)를 쓴다.
   출력 레이트는 GF1 규칙(활성 보이스 14개일 때 44.1 kHz, 32개일 때 약 19.3 kHz)을 따른다.

### 7.2 타이밍

- `gusd`는 FPGA 시각보다 **최대 1블록 늦게** 따라간다. 미래의 쓰기를 모르므로 앞서 나갈 수 없다.
- 그래서 웨이브테이블/램프 IRQ는 **최대 약 1–2 ms 늦게** 도착한다. DOSBox도 비슷한 블록 단위로 동작한다.
- 오디오 출력 지연은 ALSA 버퍼 크기에 따른다(수십 ms 예상, MidiLink와 비슷). 이 지연은 IRQ 타이밍과 무관하다.

### 7.3 배포 방식

| 방식 | 장점 | 단점 |
|---|---|---|
| **별도 데몬 (채택)** | MiSTer Main을 고치지 않는다. 코어와 따로 배포/갱신할 수 있다 | 사용자가 설치해야 한다(예: `linux/user-startup.sh`로 실행). 매직 확인으로 코어를 감지해야 한다 |
| MiSTer Main 통합 (채택 안 함) | 설치가 필요 없다. 코어 로드와 함께 시작/종료된다 | 업스트림 Main 수정과 리뷰가 필요하다 |

**결정: 별도 데몬으로 간다.** MiSTer Main은 수정하지 않는다.

- 소스 위치: 이 저장소의 `hps/gusd/` (C/C++, MiSTer Linux용 ARM 크로스 컴파일, GPLv2).
- 설치: `gusd` 바이너리를 `/media/fat/linux/`에 두고 `/media/fat/linux/user-startup.sh`에서 백그라운드로 실행한다.
- 코어 감지: FPGA 헤더 매직(`"Z486GUS1"`)을 100 ms 간격으로 확인한다. 다른 코어가 로드되면 매직이 사라지므로
  합성과 ALSA 출력을 멈추고 대기 상태로 돌아간다.
- 프로토콜 버전: FPGA 헤더의 버전 필드와 데몬 버전이 다르면 동작하지 않고 로그만 남긴다.
  코어와 데몬을 따로 갱신할 수 있으므로 버전이 맞지 않는 경우를 반드시 처리한다.
- 상태 표시: 데몬 하트비트 유무를 FPGA가 OSD에 `GUS: No daemon`처럼 표시한다(6.3절).

## 8. 성능과 정확도 요약

| 항목 | 값 (추정) |
|---|---|
| GUS I/O 쓰기 | FPGA에서 즉시 (내부 장치와 같음) |
| GUS I/O 읽기 | FPGA에서 즉시. 3x7h는 DDR 왕복 < 1 µs |
| 보이스 위치 읽기 정확도 | 약 1 ms (외삽을 켜면 더 정확) |
| 웨이브/램프 IRQ 지연 | ≤ 약 2 ms |
| 타이머 / DMA TC IRQ | FPGA에서 정확 |
| 오디오 출력 지연 | ALSA 버퍼 (수십 ms) |
| HPS CPU 사용 | 코어 하나의 몇 %, 샘플 RAM 사본 사용 시 |
| DDR 대역 | 초당 1 MB 이하 |

## 9. 위험 요소

| 위험 | 영향 | 대응 |
|---|---|---|
| `GUS_BASE` 영역이 다른 용도와 겹침 | 메모리 손상 | MiSTer Main/Linux 메모리 맵 확인, 헤더 매직 검사 |
| ALSA 경로 지연과 언더런 | 끊김, 지연 | 버퍼 크기 조정, `SCHED_FIFO`, CPU 고정(core 1) |
| 위치 폴링에 의존하는 데모 | 타이밍 어긋남 | 외삽 옵션, 블록 0.5 ms로 축소 |
| 경쟁 조건(HPS 상태가 CPU 쓰기를 덮어씀) | 잘못된 주소/볼륨 | 기준 로그 인덱스 규칙(5.5절), 시뮬레이션 검증 |
| 데몬 미설치 또는 중단 | 무음 | 하트비트 감시로 CPU 정지 방지(6.3절), OSD에 상태 표시 |
| DDR 중재로 인한 SVGA 영향 | 화면 끊김 | 프레임버퍼 우선, GUS 트래픽 제한 |
| 라이선스 | 배포 문제 | DOSBox-X/PicoGUS 코드는 GPLv2. 데몬을 별도 GPLv2 프로그램으로 배포 |

## 10. 검증 계획

### 10.1 시뮬레이션 (Verilator)

- `gus_front` 단위: 포트/레지스터 읽기·쓰기, 3x7h DRAM 쓰기·읽기, 타이머 1/2, DMA(8/16-bit, 반전, TC IRQ),
  로그 형식과 링 순환, 로그 가득 참 시 대기, 기준 로그 인덱스 경쟁 규칙.
- `gusd` 모델: 로그를 읽어 상태/이벤트를 쓰는 C++ 모델을 Verilator 테스트에 붙인다
  (DDR은 모델 메모리로 대체).
- 기존 부팅 회귀: GUS Off에서 동작이 바뀌지 않는지.

### 10.2 하드웨어

1. `gusd` 골격: 매직 감지, 하트비트, ALSA로 사인파 출력 → 믹서 경로 확인.
2. ULTRINIT / 게임 설치 프로그램의 GUS 감지(DRAM 크기 검사) 통과.
3. DMA 업로드와 단일 보이스 재생(테스트 프로그램).
4. 게임: Doom(GUS 패치), Epic Pinball, Jazz Jackrabbit, One Must Fall 2097.
5. 데모: Second Reality, Crystal Dream 2 (위치 폴링과 IRQ 타이밍 확인).
6. SVGA 고해상도 모드와 동시 사용 시 화면/오디오 끊김 확인.
